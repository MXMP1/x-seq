# x-sequence — Техническое задание и спецификация проекта

**Версия:** 2.0 (актуальная; v1.0 с React/Tone.js — в архиве)
**Статус:** MVP ядра собран и проверен headless-тестами; этап подключения FM-1 — следующий
**Целевая среда:** Chrome 153+ на Android, сервер — Node.js в Termux, открывать по `http://localhost:8080`

---

## 🎯 О проекте

**x-sequence** — веб-секвенсор (piano roll) в браузере телефона, синхронизирующий:

1. **Аудио-луп** (Web Audio API) — играет из динамика телефона, сэмпл-точно по сетке.
2. **Внешний FM-синтезатор M-VAVE FM-1** (Web MIDI API, подключение USB-C) — ноты из 16×4 сетки.

Ключевая идея: **один таймер** на `AudioContext.currentTime` + look-ahead шедулер
(25 мс будильник, 100 мс окно) — паттерн Chris Wilson «A Tale of Two Clocks».
Никаких Tone.js/сборщиков: чистый vanilla JS, zero-build (Termux + мобильный Chrome).

```
[Chrome на телефоне (localhost)]
├── Look-ahead шедулер (setInterval 25 мс — только будильник!)
│     ├── Web Audio: старт прохода лупа (sample-accurate)
│     ├── MIDI-очередь (setTimeout с калибровочным смещением) ──► USB-C ──► [FM-1] 🔊
│     └── Визуальная очередь шагов (rAF, подсветка колонки)
└── Динамик телефона 🔊 (луп)
```

## 🛠️ Стек

| Компонент | Технология | Примечание |
| :--- | :--- | :--- |
| Язык | Vanilla JS (ES-модули) | без TypeScript и сборки |
| Тайминг | Web Audio API `currentTime` | `setInterval` — только как «будильник» шедулера |
| Луп | `AudioBufferSourceNode` + пересчёт `playbackRate` | луп всегда ложится на целый такт |
| MIDI (этап 1) | **Web MIDI API** (`navigator.requestMIDIAccess`) | USB-C; Chrome for Android 152+; страница обязана быть в secure context (localhost) |
| MIDI (этап 2) | Web Bluetooth + BLE-MIDI (GATT `03B80E5A-…`) | Android не пробрасывает BLE-MIDI в Web MIDI — будет свой бэкенд с тем же интерфейсом |
| Сервер | `node server.js` (без зависимостей) | статика + Range-запросы для аудио |

## ⏱️ Принятые решения по таймингу

- **Шаг = 1/16 при 4/4**: `stepDuration = 60 / bpm / 4`; сетка = 16 шагов = 1 такт.
- **Луп**: число тактов вычисляется из длительности файла и BPM из имени
  (`bars = round(duration·bpm/240)`), затем `playbackRate = barDuration·bars / duration` —
  луп всегда выровнен по такту; смена BPM применяется на границе такта.
- **Ноты FM-1**: `noteOn [0x90|ch, note, vel]` на границе шага, `noteOff` через gate
  (50% шага). Канал — 1.
- **Калибровка MIDI**: слайдер `midiOffsetMs` (по умолчанию +25 мс; «+» = ноты звучат
  позже). Нужен, т.к. звук из динамика телефона выходит с `outputLatency` (~20–40 мс),
  а USB-MIDI почти мгновенный. Настраивается на слух.
- **Очередь отправки MIDI**: свои `setTimeout` (время цели − текущее + смещение).
  Параметр `timestamp` у `output.send()` есть, но в Chromium исторически ненадёжен —
  включён отдельной галочкой «экспериментально», архитектура от него не зависит.
- **Стоп**: явные `noteOff` для звучащих нот + CC123, отмена таймеров, микро-фейд лупа (без щелчка).
- **Фон вкладки**: lookahead расширяется до 2.5 с (браузер троттлит таймеры); Wake Lock на время игры.

## ✅ Проверено (npm test, виртуальные часы)

- Дрейф сетки за 10 минут при 120 BPM: отклонение от идеальной прямой < 1e-9 мс;
  4800 шагов ровно по 125.000 мс; 300+ проходов лупа ровно по 2.000 с.
- Парность noteOn/noteOff и gate: ошибка длительности < 1e-7 мкс; залипших нот нет.
- Смена BPM на лету: граница ровная, луп пересчитан (rate 1 → 1.333 при 90 BPM).
- Стоп: noteOff + CC123 досланы, таймеры очищены, повторный стоп безопасен.

## ⚠️ Ограничения

- Web MIDI/Bluetooth работают **только в secure context**: `http://localhost:8080` или HTTPS.
  Открытие по LAN-IP (`http://192.168.x.x:8080`) — API отвалятся.
- На Android Web MIDI видит **только USB-MIDI**; BLE — исключительно через Web Bluetooth (этап 2).
- «Идеальная» синхронность двух трактов (динамик телефона ↔ FM-1) достигается калибровкой
  на слух: остаётся малый джиттер BLE/USB, среднее смещение уводится слайдером в ноль.
